## Про проєкт

**Microclimate Monitor** — кросплатформний десктопний застосунок для моніторингу та аналізу параметрів мікроклімату в приміщеннях (житлові кімнати, навчальні класи, лабораторії).

Система в режимі реального часу відстежує температуру, вологість та рівень $\text{CO}_2$, будує інтерактивні графіки за вибрані проміжки часу, оцінює ергономічний комфорт середовища та своєчасно сповіщає про критичні відхилення від норм.

* **Автор:** Базюк Маркіян, студент групи ІПЗ-31 (2026).
* **Дисципліна:** Кросплатформне програмування / Методи проєктування програм (C#, .NET 10, Avalonia UI).

## Основні можливості

* **Моніторинг кімнат:** перегляд списку приміщень із динамічним оновленням поточних показників (температура, відносна вологість, концентрація $\text{CO}_2$).
* **Оцінка комфорту:** зрозумілі вербальні статуси середовища (*«Добре»*, *«Душно»*, *«Холодно»*, *«Жарко»*, *«Сухо»*, *«Волого»*).
* **Аналітичні графіки:** візуалізація динаміки показників за 1 годину, 24 години або 7 днів з інтелектуальним алгоритмом проріджування точок (**Downsampler**) для високої швидкодії UI.
* **Гнучка система сповіщень:**
  * Колірна диференціація за рівнем критичності (Warning / Critical).
  * Ручне квітування (кнопка *«Підтвердити»* для архівації алерта).
  * **Антидребезг (Debounce):** обмеження на генерацію повторного сповіщення не частіше 1 разу на 10 хвилин для зв'язки `Кімната + Правило`.
* 📡 **Симуляція сенсорного шару:** генератор реалістичного дрейфу показників, шумів, пропусків замірів і сценаріїв «провітрювання». Легка заміна джерела даних завдяки інтерфейсу `ISensorSource`.
* **Захист від аномалій:** автоматична фільтрація викидів (`NaN`, `Infinity`, неможливі фізичні величини).
* **Надійне збереження:** транзакційний пакетний запис у локальну БД SQLite через Entity Framework Core в режимі `WAL`.

## Схема та безпека даних (C5)

* **Схема таблиць:** `Rooms`, `Sensors`, `Measurements`, `Rules`, `Alerts`.
* **Реляційна цілісність:** суворі первинні (`PK`) та зовнішні (`FK`) ключі, налаштовано каскадне видалення зв'язаних даних при видаленні кімнати.
* **Індексація:**
  * `UNIQUE Index` на полі `Rooms.Name`.
  * Складений індекс `(SensorId, Timestamp)` у таблиці `Measurements` для швидкої вибірки замірів за проміжок часу без повного сканування таблиці.
* **Безпека:** усі запити виконуються через ORM із строгою параметризацією (повний захист від SQL Injection). Пакетне збереження відліків обгорнуто в атомарні транзакції.

### Розташування бази та логів:
Файл `microclimate.db` та папка `logs/` автоматично розміщуються у системній директорії користувача:
* **Windows:** `%LocalAppData%\MicroclimateMonitor\`
* **Linux:** `~/.local/share/MicroclimateMonitor/`
* **macOS:** `~/Library/Application Support/MicroclimateMonitor/`

> **Повна ізоляція:** щоб скинути стан програми до початкового («демо»), закрийте застосунок і просто видаліть файл `microclimate.db`.

## Обробка крайніх випадків та відмовостійкість (C2)

Відповідно до чекліста критерію надійності ПЗ, у системі реалізовано:

| № | Випадок | Як оброблено в системі |
| :---: | :--- | :--- |
| **1** | **Валідація введення** | Перевірка назв кімнат на пусті значення та дублікати; обмеження допустимих діапазонів числових меж правил у ViewModels. |
| **2** | **Порожні / некоректні дані** | Обробка випадків повернення сенсором значень `NaN`, `±Infinity` або пропусків відліків — некоректні пакети відсікаються `MeasurementFilter` без зупинки циклу. |
| **3** | **Безперервність без збоїв** | Винятки з'єднання з базою або таймаути симулятора всередині `PollingService` перехоплюються через `try-catch`, фіксуються в лог, а сервіс продовжує штатну роботу на наступній ітерації. |
| **4** | **Межові значення** | Коректна обробка точок на стиках порогів правил; безпечна робота алгоритму `Downsampler` при вибірках з малою кількістю точок ($N \le 2$). |
| **5** | **Відсутність неперехоплених винятків** | Підключені глобальні обробники `AppDomain.CurrentDomain.UnhandledException` та `TaskScheduler.UnobservedTaskException`, які виключають аварійний «тихий» краш програми і гарантують запис інциденту в журнал. |

## Швидкий запуск (E3)

### Системні вимоги:
* **.NET 10 SDK** (перевірка: `dotnet --version`)
* **Git**
* Графічне середовище (Windows 10/11, macOS або Linux з X11/Wayland)

Базу даних встановлювати не потрібно — SQLite створюється і наповнюється тестовими даними автоматично при першому старті.

```bash
# 1. Клонувати репозиторій
git clone https://github.com/jasonv00rh33s/MicroclimateMonitor.git
cd MicroclimateMonitor

# 2. Відновити залежності
dotnet restore

# 3. Запустити десктопний застосунок
dotnet run --project src/Microclimate.App
```

### Перші кроки після запуску:
1. За кілька секунд після старту `PollingService` підтягне перші вимірювання для трьох попередньо налаштованих кімнат.
2. Оберіть потрібну кімнату зі списку ліворуч — відкриється детальна панель із показниками та графіком.
3. У випадаючих списках можна змінити тип показника (Температура / Вологість / $\text{CO}_2$) та таймфрейм (1 год / 24 год / 7 днів).
4. Оскільки в симуляторі рівень $\text{CO}_2$ має позитивний тренд, за кілька хвилин спрацює контрольне правило і на панелі з'явиться алерт, який можна закрити кнопкою **«Підтвердити»**.

## Тестування та метрики покриття (C3)

Запуск тестового набору:
```bash
dotnet test
```

Генерація детального звіту покриття коду:
```bash
# Встановлення генератора звітів (одноразово)
dotnet tool install --global dotnet-reportgenerator-globaltool

# Прогін тестів зі збором статистики Cobertura
dotnet test --collect:"XPlat Code Coverage" --results-directory ./coverage

# Формування звіту
reportgenerator \
  -reports:"./coverage/**/coverage.cobertura.xml" \
  -targetdir:"./coverage/report" \
  -reporttypes:"TextSummary;MarkdownSummary"
```
Результати доступні у файлі `coverage/report/Summary.txt`
